# BUG-2026-07-30T130100: Silent fallback on VERSION read failure

## Problem

If the `VERSION` file is missing or unreadable, the handler silently serves `vunknown` with HTTP 200 and no error indication. This masks deployment failures where the VERSION file isn't properly updated.

- **Actual:** Missing VERSION → `vunknown` in footer, no log output, HTTP 200
- **Expected:** Error should be logged for observability
- **Reproduce:** 1. `rm VERSION` 2. `go run .` 3. `curl http://localhost:8080/` 4. Shows "vunknown" with no error

## Root Cause

`os.ReadFile("VERSION")` error is silently swallowed in the `if err == nil` branch with no `else` clause for logging.

## Resolution

**Fixed:** 2026-07-30
**Root cause confirmed:** `os.ReadFile` error silently swallowed; no logging in else branch
**Fix applied:** Added `log.Printf("VERSION read error: %v", err)` in the else branch
**Hardening added:** Regression test `TestHandlerMissingVersionFile` verifies fallback behavior and HTTP 200
**Evidence:** All 5 tests pass (`go test ./... -count=1 -timeout 120s`)
**Commit:** `fix(handler): log VERSION read errors instead of silent fallback`

### Behavioral Proof
