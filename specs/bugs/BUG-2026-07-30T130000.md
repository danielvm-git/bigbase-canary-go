# BUG-2026-07-30T130000: Handler missing Content-Type header

## Problem

The Go HTTP handler writes an HTML response (`<h1>bigbase canary (Go)</h1><footer>v%s</footer>`) but never sets the `Content-Type` header. Go's `net/http` defaults to `text/plain` when no Content-Type is set, so browsers running the app locally would render the HTML as plain text.

The bigbase deploy platform adds `Content-Type: text/html; charset=utf-8` in production, so this only manifests when running `go run .` locally.

- **Actual:** `curl -I http://localhost:8080/` shows no Content-Type header (Go defaults to text/plain)
- **Expected:** Handler should set `Content-Type: text/html; charset=utf-8`
- **Reproduce:** 1. `go run .` 2. `curl -I http://localhost:8080/` 3. Observe missing Content-Type

## Root Cause

`handler()` calls `fmt.Fprintf(w, ...)` with HTML content but never calls `w.Header().Set("Content-Type", ...)` before writing the response body.

## Resolution

**Fixed:** 2026-07-30
**Root cause confirmed:** Handler writes HTML without declaring Content-Type
**Fix applied:** Added `w.Header().Set("Content-Type", "text/html; charset=utf-8")` before `fmt.Fprintf`
**Hardening added:** Regression test `TestHandlerSetsContentType` verifies header is set
**Evidence:** All 5 tests pass (`go test ./... -count=1 -timeout 120s`)
**Commit:** `fix(handler): set Content-Type header for HTML response`

### Behavioral Proof

```
$ go run . &
$ curl -sI http://localhost:8080/ | grep content-type
content-type: text/html; charset=utf-8
```
