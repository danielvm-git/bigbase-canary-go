# BUG-2026-07-30T130300: Dead logic in deploy health check

## Problem

The health check in `deploy.yml` accepts HTTP 301 and 302 as success codes, but the Go handler never returns redirects — it always returns 200. This dead logic could mask a misconfiguration if the platform starts returning redirects unexpectedly.

- **Actual:** Health check accepts `200 || 301 || 302`
- **Expected:** Health check should only accept `200`
- **Reproduce:** Read `deploy.yml` lines 69-71, compare with `main.go` handler (always 200)

## Root Cause

Health check was copied from a template designed for redirect-capable sites. The canary site never redirects.

## Resolution

**Fixed:** 2026-07-30
**Root cause confirmed:** Template copy-paste; handler never redirects
**Fix applied:** Removed `|| "$STATUS" = "301" || "$STATUS" = "302"` from health check condition
**Hardening added:** Tighter health check prevents false-positive deploy success
**Evidence:** `grep -A2 'STATUS.*200' .github/workflows/deploy.yml` shows only `200`
**Commit:** `fix(deploy): accept only HTTP 200 in health check`
